# Next Portfolio Case Study Plan

## Purpose

Keep the portfolio continuously updated with real, production-oriented work instead of allowing it to become a static collection of old projects.

## How to Add the Next Case Study

Every new portfolio case study will follow the same three-beat structure:

### 1. Problem

Explain the real-world problem the project was created to solve and why it matters.

### 2. What I Did

Explain my engineering contribution, architecture, important technical decisions, technologies used, and the difficult parts I solved.

### 3. What Came of It

Document the measurable or demonstrable outcome, such as a working system, deployed application, benchmark, test results, automation, performance improvement, or other concrete evidence.

## Portfolio Update Workflow

1. Select a completed project with meaningful engineering work.
2. Write the Problem → What I Did → What Came of It case-study summary.
3. Add or update the project data in `src/data/projects.ts`.
4. Add the verified GitHub repository URL.
5. Add a live demo URL when one exists.
6. Add relevant project screenshots or other proof.
7. Check the case study on mobile, tablet, and desktop.
8. Verify all project and external links.
9. Run `npm run lint`.
10. Run `npm run build`.
11. Run `git diff --check`.
12. Commit the portfolio update.
13. Push the change to `main`.
14. Verify the updated live deployment.
15. Capture evidence and update the FlyRank track submission.
